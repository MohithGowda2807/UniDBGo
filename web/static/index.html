Unified Multi-DB Interface

CRITICAL GAP

Standard Go requires separate drivers, connection strings, and query patterns for each database. UniDB provides one API for all.

❌ Standard Go
// Need separate handles per DB
pgDB, _ := sql.Open("postgres",
  "host=localhost port=5432...")
myDB, _ := sql.Open("mysql",
  "root:pass@tcp(localhost:3307)/demo")

// Different placeholder syntax!
pgDB.Query("...WHERE id = $1", 1)
myDB.Query("...WHERE id = ?", 1)
// MongoDB? Completely different API!
✅ UniDB-Go
// ONE interface for everything
db, _ := api.Connect(
  "postgres://user:pass@localhost/mydb",
  api.WithMaxPool(20),
)

// Same API, any database
db.Query(ctx, "SELECT * FROM users")
db.Exec(ctx, "INSERT INTO ...")
db.BeginTx(ctx, nil) // Transactions too

SQL → AST Parsing Engine

INNOVATION

Go's database/sql treats every query as an opaque string — zero understanding of structure. UniDB parses SQL into a full AST.

❌ Standard Go
// Go sees this as just a string:
query := "SELECT u.name FROM users u"

// No way to:
// - Extract table names
// - Detect joins
// - Find columns
// - Identify subqueries
// It's completely OPAQUE
✅ UniDB-Go
ast, _ := parser.Parse(query)

// Full structural understanding:
// ast.Type     → "SELECT"
// ast.Tables   → [{Name:"users"}]
// ast.Fields   → [{Name:"name"}]
// ast.Joins    → [...]
// ast.Conditions → [...]
// Enables security, routing, planning!

Multi-Layer Security Engine

CRITICAL GAP

Standard Go only has parameterized queries. UniDB inspects the syntax tree of every query: tautologies, stacked statements, UNION extraction, comment truncation and timing functions.

❌ Standard Go
// Only protection: parameterized queries
db.Query("SELECT * FROM users WHERE id=$1", id)

// But if developer writes:
db.Query("SELECT * FROM users WHERE id=" + id)
// → SQL INJECTION! No warning!
// No detection. No protection.
// No exfiltration alerts.
✅ UniDB-Go
db.Use(security.SecurityMiddleware(engine))

// V1: tautologies   (OR 1=1, OR 0x41=0x41)
// V2: piggy-backing (; DROP TABLE ...)
// V3: exfiltration  (UNION, restricted tables)
// + comment truncation, SLEEP()/BENCHMARK()

// Auto-blocks attacks, flags suspicious
// queries — ZERO developer effort!

Cross-Database Federation

INNOVATION

In standard Go, joining data across Postgres and MySQL means manual nested loops (O(n²)). UniDB does parallel fetch + hash join automatically.

❌ Standard Go
// Manual cross-DB join — PAINFUL
pgRows, _ := pgDB.Query("SELECT...FROM users")
myRows, _ := myDB.Query("SELECT...FROM orders")

// O(n²) nested loop join!
for _, u := range users {
  for _, o := range orders {
    if u.ID == o.UserID {
      fmt.Println(u.Name, o.Total)
    }
  }
}
✅ UniDB-Go
// ONE query, automatic federation
db.Query(ctx, `
  SELECT u.name, o.total
  FROM postgres.users u
  JOIN mysql.orders o
  ON u.id = o.user_id
`)
// → Step 1: Parallel SCAN postgres
// → Step 2: Parallel SCAN mysql
// → Step 3: Hash Join in-memory (O(n+m))

Probabilistic Dialect Router

Naive Bayes

Go's database/sql has zero query intelligence. UniDB uses a Naive Bayes classifier to predict the optimal database & dialect for any query.

❌ Standard Go
// Developer must know which DB to use
if isMySQL {
  myDB.Query("...WHERE id = ?")
} else if isMongo {
  collection.Find(bson.M{...})
} else {
  pgDB.Query("...WHERE id = $1")
}
// Manual, error-prone, no intelligence
✅ UniDB-Go
// Naive Bayes model detects the dialect:
model.Predict("...WHERE id = $1")
// → {DB: postgres, Dialect: PostgreSQL}

model.Predict("...JSON_EXTRACT(data)")
// → {DB: mysql, Dialect: MySQL}

model.Predict(`{"find": "users"}`)
// → {DB: mongodb, Dialect: MQL}

Middleware Pipeline

ARCHITECTURE

database/sql has no concept of interceptors. UniDB provides composable middleware — stack security, metrics, caching, and custom logic.

❌ Standard Go
// No middleware concept at all
db.Query(ctx, query) // Direct to driver

// Want logging? Wrap manually
// Want security? Write custom code
// Want metrics? More boilerplate
// Want caching? Even more code
// None of this is composable!
✅ UniDB-Go
// Composable middleware pipeline
db.Use(security.SecurityMiddleware(eng))
db.Use(metrics.MetricsMiddleware())
db.Use(myCustomMiddleware())

// Every query auto-flows through:
// Security → Metrics → Custom → Driver
// Clean chain-of-responsibility pattern

db.SetMaxIdleConns(5)

// If load spikes → connections exhausted
// If load drops → idle connections wasted
// If DB fails → no circuit breaker
// App keeps hammering dead DB!
✅ UniDB-Go
pool := pool.NewConnectionPool(20, createFn)
// AutoTune() goroutine monitors every 5s:
// → Exhausted > 5? Scale UP (+5)
// → Idle > 10?     Scale DOWN (-2)

mgr.ExecuteWithBreaker("postgres", func(){
  // 5 failures → circuit OPENS
  // 30s timeout → auto RECOVERS
})
